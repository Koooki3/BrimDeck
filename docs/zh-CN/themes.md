# 面板主题制作指南

BrimDeck 的刘海、胶囊、指示条、配额提示、展开面板及其弹出层都由“面板主题”着色。主题在 **设置 › 面板主题** 中选择，分三类：

| 类别 | 主题 |
| --- | --- |
| 基础 | 跟随系统、深色（默认，即原有的纯黑外观）、浅色、液态玻璃（浅色）、液态玻璃（深色） |
| 主题扩展 | One Dark Pro、GitHub Dark、GitHub Light、Dracula Official、Night Owl、海岛假日、海岛假日 2、像素方块、赛博朋克：边缘行者（示例）、明日方舟：终末地 |
| 自定义 | 主题文件夹中的主题文件，可在设置中新建、编辑与删除 |

每个主题会分别记住你在它下面修改的应用列主题、预警、告警颜色和时间的样式与配色：切换到其他主题时保存，切换回来时恢复。第一次选择的主题使用它自己的配色和推荐的时间样式。在“配额与统计”“收起外观”中恢复默认，恢复的是当前主题的默认配色。

One Dark Pro、GitHub Dark、GitHub Light、Dracula Official、Night Owl 移植自开源的 VS Code 主题，配色按各自的 MIT 许可证使用：[One Dark Pro](https://github.com/Binaryify/OneDark-Pro)、[GitHub Theme](https://github.com/primer/github-vscode-theme)、[Dracula Official](https://github.com/dracula/visual-studio-code)、[Night Owl](https://github.com/sdras/night-owl-vscode-theme)。各项目的版权与许可声明随程序附在 `ThirdPartyNotices.txt` 中。

## 在设置中修改颜色

不写文件也可以调整主题。在 **设置 › 面板主题** 的“颜色”部分：

- **背景、前景、强调色**：修改其中一项时，与它相关的颜色会按它重新生成。背景决定面板底色和弹出层；前景决定文字、分隔线和控件底色；强调色决定键盘焦点、选中的日期和日期范围。背景从深色改为浅色（或反过来）时，如果原来的前景在新背景上看不清，前景也会随之调整。
- **高级设置**：逐项列出全部颜色项、应用默认颜色和效果（边缘描线宽度、阴影、扫描线）。半透明的颜色在取色时保留原来的不透明度。

修改过的项会标出“修改未保存”，可以单独撤销，也可以用“撤销全部修改”一次撤销。**修改只在保存后生效**：保存前，面板和主题卡片都保持原样。有修改时，“自定义”中的卡片会变为保存卡片：

- **保存当前主题**（蓝色，替代“以当前主题新建”）：把当前主题连同修改保存为一个新的自定义主题，并切换到它。内置主题不能直接修改，只能这样保存。
- **覆盖当前主题**（黄色，替代当前所选自定义主题的卡片）：把修改写入这个主题的文件。只改写修改过的值，注释和排版保持不变。

未保存的修改在 BrimDeck 运行期间保留；退出 BrimDeck 后将会丢失。表面渐变、边缘渐变、时间的预设颜色与渐变，以及颜色选择器的预设色，仍需在主题文件中修改。

## 主题文件

主题像 VS Code 的主题扩展一样，是一个 JSON 文件：

- 主题文件夹：`%LOCALAPPDATA%\BrimDeck\themes`（设置页的“打开主题文件夹”）。
- 文件夹中的每个 `*.json`，以及每个子文件夹中的 `theme.json`，都是一个主题。
- 文件中可以写注释（`//`）和结尾逗号；不认识的属性会被忽略。
- 每个主题都有一个**基础主题**（`base`，默认 `dark`），文件只需写出与基础主题不同的部分。

最简单的主题只有几行：

```json
{
  "id": "midnight-teal",
  "name": "午夜青",
  "base": "dark",
  "colors": { "surface": "#04161A", "accent": "#2DD4BF", "clock": "#5EEAD4" }
}
```

完整模板见 [`theme-template.json`](../../src/BrimDeck.Core/Templates/theme-template.json)：它列出了全部颜色项、应用颜色和效果，每一项都注明了用途和对比度下限。设置页的 **以当前主题新建** 会把当前主题的全部取值填进这个模板，保存为一个新的自定义主题并切换到它；之后可以用“打开主题文件夹”或“当前主题”中的文件链接打开它。在设置页显示期间保存主题文件，设置页会自动重新加载，面板随即更新。

### 颜色项（colors）

颜色写作 `#RRGGBB` 或 `#AARRGGBB`（AA 为不透明度）。括号中是对比度下限，按 WCAG 2 的算法计算。文字三级、`menuDetail`、`accent` 和 `danger` 要在面板底色（含渐变的每个色标）与弹出层底色上都达标；`liked`、`clock`、`equalizer` 只看面板底色；`onAccent` 看强调色，`indicatorProgress` 看指示条。另外，文字也会落在填充色上：`textPrimary` 在 `fillSelected`、`pressed`、`input`、`rangeFill`、`tooltip`、`bubble` 上，`textSecondary` 在 `fill`、`hover` 上，都需要 4.5:1。

| 键 | 用途 |
| --- | --- |
| `surface` | 刘海、胶囊和展开面板的底色，总是不透明 |
| `textPrimary` | 标题、数字（7:1） |
| `textSecondary` | 标签（4.5:1） |
| `textTertiary` | 重置时间、备注等辅助小字（4.5:1） |
| `accent` / `onAccent` | 键盘焦点、选中的日期（3:1） / 其上的文字，如通知的主按钮（4.5:1） |
| `danger` | 错误与暂停同步（4.5:1） |
| `liked` | 已喜欢的歌曲（3:1） |
| `clock` | 时间颜色选“主题默认色”时的颜色（4.5:1） |
| `equalizer` | 律动条不跟随封面时的颜色（3:1） |
| `hairline` `track` `ringTrack` `fill` `fillSelected` `hover` `pressed` `outline` | 分隔线、进度底轨、分段控件、悬停与按下、描边 |
| `popup` `popupBorder` `input` `rangeFill` | 菜单与弹出层，日期输入框和日期范围 |
| `coverPlaceholder` `coverOutline` `scrollThumb` | 无封面占位、封面描边、滚动条（滑块在底色上 2:1） |
| `rim` `shadow` | 表面内侧描线；收起时的阴影（亮色加零偏移即为辉光） |
| `indicator` `indicatorProgress` | 指示条与其上的播放进度（2:1） |
| `switchFill` `seekRail` `rowDivider` `rowHover` | 工具栏页面切换底色、播放进度底轨、模型明细的行分隔与悬停 |
| `menuDetail` | 播放来源菜单中的歌名（3:1） |
| `tooltip` `tooltipBorder` `bubble` `bubbleBorder` | 面板上的提示框、拖动进度时的时间气泡 |

### 应用颜色（apps）

配额列、进度条和配额环的默认颜色，键为 `claude`、`codex`、`antigravity`、`cursor`、`zcode`、`dsh`、`grokBot`、`kimi`、`opencode`、`manual`（所有手动填写的来源）、`other`，以及 `warning`、`critical`（这两种同时也是文字，需 4.5:1）。在“配额与统计”中为某列选过颜色后，该列使用所选颜色。

### 时间（clock）

主题推荐的时间样式与配色。在设置中选中主题时，收起形态的时间会切换为推荐值，之后仍可在“收起外观”中自行修改；各字段与颜色一样逐项继承：只写 `style` 时，颜色沿用基础主题的推荐。

```json
"clock": { "style": "segment", "color": "default", "custom": "#B9A8FF", "gradient": ["#FF79C6", "#BD93F9", "#8BE9FD"] }
```

`style` 取 `minimal`、`stacked`、`digits`、`dots`、`segment`、`neon`、`serif`、`wide`、`condensed`、`pixel`（方块点阵，像素方块主题推荐）、`tektur`、`rounded`（圆润的 Fredoka 字体，海岛假日 2 主题推荐）；`color` 取 `default`（即上面的 `clock` 颜色）、`amber`、`cyan`、`pink`、`lime`、`custom`、`gradient`、`cover`。`palette` 给出本主题下“琥珀、青色、粉色、柠檬绿”四个色块的颜色，`gradients` 给出本主题提供的预设渐变（一到八组，每组正好三个颜色），二者都需在底色上达到 4.5:1。切换主题时，正在使用的预设渐变会换成新主题同一位置的那一组。`custom` 在 `color` 为 `custom` 时使用；`gradient` 必须正好三个颜色，在 `color` 为 `gradient` 时使用。浅色主题下霓虹与数码管的辉光会自动减弱，避免数字发虚。

### 颜色选择器预设色（swatches）

设置中颜色选择器下方的十二个色块。不写时，取本主题的应用颜色、预警告警色和时间颜色（去重，不足时用相邻颜色的中间色补齐）；深色主题保留原来的十二色。此项不继承。

### 效果（effects）

| 键 | 作用 | 范围 |
| --- | --- | --- |
| `surfaceGradient` | 从上到下叠在底色上的渐变，2 到 8 个颜色 | |
| `rimGradient` | 从左到右的描线渐变，替代 `rim` | |
| `rimWidth` | 描线宽度 | 0–3 |
| `shadowBlur` `shadowDepth` `shadowOpacity` | 阴影的模糊、下移距离与不透明度 | 0–40、0–12、0–1 |
| `scanlines` | 横向扫描线，以主要文字色按此不透明度绘制 | 0–0.12 |
| `glass` | 玻璃材质：`tint` 是叠在桌面上的半透明色调（不透明度须在 0 和 1 之间），`edge` 是沿内缘聚集的光（0–1），`highlight` 是这道光的颜色。见下方“玻璃” | |
| `pixel` | 像素风：轮廓的曲线变成这么多 DIP 的阶梯（按整设备像素取整），面板上的圆角变成直角，文字不做平滑；配合 `rimGradient` 时描线变成斜面，第一个颜色照亮朝上和朝左的边，最后一个颜色压暗朝下和朝右的边。不能与 `glass` 同时使用（含从基础主题继承来的），否则文件报错 | 0，或 1–4 |
| `cut` | 切角：轮廓的曲线变成 45° 的直线切角，每个角的切边不长于 `cut` 与它自己的圆角半径，刘海的肩部变成笔直的斜线，像工业铭牌；四个角都和高度的一半一样圆的轮廓（胶囊）保持圆头，圆角比高度的一半小 8 DIP 以上才完全变成切角，中间逐点过渡，所以胶囊展开成面板时形状是连续的。不能与 `glass` 同时使用（含继承来的），否则文件报错；与 `pixel` 同时存在时以像素阶梯为准。面板里控件的圆角也收到 2 DIP 以内（胶囊形的开关与分页除外） | 0–16 DIP |
| `texture` | 配合 `pixel`：以像素大小为单位、略亮或略暗于底色的方块，像方块的颗粒。最亮和最暗的方块与渐变色标一样参与对比度检查；没有 `pixel` 时不生效 | 0–0.12 |
| `decor` | 画在表面里、内容之下的安静图案，每个值分别继承（夜间外观只写 `sea` 时沿用白天的 `at` 与 `line`）：`horizon` 在高度 `at`（未设置时为 0.62）处以下铺一片海（`sea`），沿海平线有一道光（`line`，不透明度不限，同样检查对比度）；`caustics` 是海平线以下柔和的水波光纹（没有海平线时铺满整个表面）；`palm` 是展开面板右上角、海平线以上的棕榈叶影；`hud` 是左下角与右上角（悬挂在屏幕边上的岛改为右下角）的 45° 切角（`chamfer`），各配一个六边形刻点；`hatch` 是展开面板底边右端的一条 45° 斜纹（印刷在面板上的“封存”标记）；`tab` 是底边左端的一小段信号色横条（像导航当前项的竖条）。`hatch` 与 `tab` 各写 `{ "color": "#AARRGGBB" }`，只在展开面板（高度 56–80 DIP 之间淡入）和通知窗上画，通知窗里 `tab` 是左缘的竖条。完全透明的颜色会关掉该部分（例如在夜间外观里）。文字对比度按海面（海平线处与最深处）、海平线光带和图案叠加后的颜色检查 | `at` 0.3–0.9，水光不透明度 ≤ 0.2，叶影 ≤ 0.12，`chamfer` 0–10 |

#### 玻璃（glass）

玻璃主题的表面不是纯色，而是叠在桌面上的半透明色调，岛下的桌面会透出来。可读性仍然由规则保证：文字的对比度按色调叠在**纯黑**和**纯白**桌面上两种极端情况分别检查，所以浅色玻璃的色调需要较浓（约 75%）。玻璃的边缘有两层光：`rimGradient` 是镜面高光描线，`edge` 是沿内缘渐弱的集光，像厚玻璃的边。

下列情况玻璃改为画 `surface` 这个不透明底色：Windows 关闭了“透明效果”（设置 › 个性化 › 颜色），或处于高对比度。设置页的“当前主题”会注明原因。玻璃岛下的阴影只画在岛外，不会透过玻璃显出来。

Windows 支持时，玻璃下面的桌面是模糊的：BrimDeck 在岛的正下方放一个只显示模糊背景的窗口（Windows 合成引擎的宿主背景画笔，由 DWM 模糊），形状与岛一致。岛在展开、收起、换页、开关机时变形，两个窗口无法在同一帧变形，所以这期间模糊会先让开，岛静止约 0.1 秒后再按新形状淡入，任何时候都不会露出岛外的方块。关闭透明效果、高对比度、节电模式、远程桌面或系统不支持时没有模糊，玻璃改为“清透”：背后的内容以淡淡的影子透出，可读性规则照样成立。

### 动效（motion）

主题在 BrimDeck 自己的窗口上的动效：灵动岛上缓慢的环境光，以及对指针和键盘的反馈。与效果一样，这一节沿继承链逐项合并，主题只需写出要改的项。每个值都限制在下表范围内（超出时取最近的端点），因此任何主题文件都无法造成闪烁：亮度变化每秒不超过三次。BrimDeck 设置或 Windows 中关闭动画、或处于高对比度时，一切都不动；灵动岛隐藏或正在关机、会话锁定、开启节电模式、或灵动岛所在显示器上有最大化或全屏窗口在前台时，环境光也会停止（与动态壁纸的暂停条件一致）；面板收起时，按压留下的粒子立即消失。设置窗口保留自己的悬停与焦点样式。

`ambient`（环境光）：周期单位为秒，0 表示关闭该效果。

| 键 | 作用 | 范围 |
| --- | --- | --- |
| `breathe` `breatheDepth` | 描线每个周期轻微变暗再恢复一次；变暗的幅度 | 3–30、0–0.35 |
| `drift` | 描线渐变的颜色在这段时间内移动一个宽度 | 4–60 |
| `sweep` `sweepOpacity` | 每个周期有一道淡淡的扫描线自上而下扫过（历时 2.4 秒）；其强度 | 6–120、0–0.12 |
| `flicker` `flickerDepth` | 霓虹每个周期轻轻暗下一次（历时 1.2 秒）；暗下的深度 | 20–300、0–0.15 |

对指针的反馈画在控件实际可见的形状上，不会画在布局框外，也不会跟随指针。按压在按键按下时立即响应，按住时保持，松开时完成（在别处松开则退回）；键盘焦点所在的控件按 Space 或 Enter 时同样有按压反馈，但不放粒子。

| 键 | 作用 | 取值 |
| --- | --- | --- |
| `hover` | 悬停标记：`none`、`reveal`（淡填充，顶部受光的边）、`lift`（外侧柔和阴影，顶部亮边）、`underline`（淡填充，底部 2 px 条）、`caret`（行高亮，左侧光标条）、`brackets`（HUD 四角括号）、`sheen`（双色渐变与细边）、`glow`（暖色内发光与一点高光）、`lens`（玻璃珠顶部聚光，顶部亮边）、`wave`（淡填充，底部涌来一道小浪后静止）、`slot`（方形高亮与实心内框，像物品栏的格子） | 旧名：`spot` = reveal、`edge` = underline、`neon` = brackets |
| `hoverStrength` | 悬停标记的强度 | 0–0.3 |
| `press` | 按压：`none`、`shade`（形状变深，边缘加实）、`sink`（阴影收起，像被按下）、`indicator`（底部条变为强调色）、`select`（从光标处扫出选区）、`lock`（括号扣紧，色差残影和故障切片；松开时一道扫描线）、`sparkle`（色调加深；松开时星光）、`ember`（暖光鼓起；松开时萤火）、`bevel`（斜面翻转：左上压暗、右下照亮，像像素按钮被按下）、`jelly`（玻璃上的光被压扁变宽变矮，只压暗底边，松开时回弹并略微过冲）、`splash`（按下时从控件自己的边缘向外扩一圈水波，完成的按压松开时再扩一圈更淡的，每圈 320–400 ms，减速收尾） | 旧名：`pulse`、`ripple` = shade，`ring` = lock |
| `pressStrength` | 按压的强度 | 0–0.35 |
| `particles` | 完成一次按压后从控件边缘短暂出现的粒子：`none`、`dust`、`pixel`、`spark`、`star`、`firefly`、`neon`、`rain`（从底边落下 3–4 道 1×6 DIP 的细斜线，不透明度至多 0.25，约 1 秒）、`bubble`（从底边冒出 3–5 个半径 2–4 DIP 的气泡，上浮 22–32 DIP，0.8–1.2 秒，描边不透明度至多 0.5） | |
| `trail` | 这些粒子的强度；0 表示不显示 | 0–0.6 |
| `focus` | 键盘焦点落下时的短暂强调（连续按 Tab 时只在停顿后的第一次出现，其余只显示静态焦点框）：`none`、`ring`、`glow`、`brackets`、`caret` | 旧名：`neon` = brackets |
| `pace` | 按此倍数缩放主题对指针和键盘的反馈节奏（悬停、按压、焦点、粒子）；与设置中的“展开与收起动画时长”无关 | 0.6–1.6 |
| `steps` | 0 为平滑；2 到 8 表示分成这么多段硬切，带机械感。无论点得多快，故障切片和扫描线每秒最多两次 | 0、2–8 |
| `color` | 主标记的颜色（悬停与焦点） | 颜色项、`#RRGGBB` 或 `system`（Windows 强调色） |
| `secondary` | 第二色调：渐变的终点、阴影、残影或中性条 | 同 `color` |
| `highlight` | 按压瞬间的颜色：指示条、选区、扫描线、星光、萤火、雨丝、气泡 | 同 `color` |
| `spring` | 弹簧给多少弹性（拖动改尺寸、`jelly` 松手回弹），频率固定为监控页的 16 rad/s：`firm`（阻尼 0.85，几乎不过冲）、`default`（0.70）、`jelly`（0.50，回弹两次） | |
| `particleMs` | 按压留下的粒子存活多久（毫秒），每个粒子仍保留自己的小幅差异；0 用各样式自带的（rain 约 1000） | 0、300–2400 |
| `sliceMs` | `lock` 按下时故障切片停留多久（毫秒）；0 约 70 | 0、50–160 |
| `scanMs` | `lock` 松开时扫描线扫过所用的时间（毫秒）；0 约 140 | 0、100–400 |
| `splashMs` | `splash` 每圈水波扩散所用的时间（毫秒）；第二圈在松开时出现，但不早于第一圈扩到一半；0 约 360 | 0、300–800 |

动效颜色与主题外选择的其他颜色一样，会按底色保证可读。默认的深色、浅色主题（以及没有任何 `motion` 段的主题）不在控件上画任何标记，控件保持自己的悬停与按下样式。“跟随系统”主题使用 Windows 强调色；基底主题有反馈时改为安静的 Fluent 反馈（`reveal` 与 `shade`，基底为 `lift`、`sink` 时保留），基底是默认深色、浅色时同样不画标记；没有环境光、粒子和分段，基底主题的强度与节奏保留。`Templates/theme-template.json` 列出了所有键及其默认值。

### 日夜外观（night、dusk、daylight）

主题可以带一个夜间外观：`night` 里写出夜间要改的 `colors`、`apps`、`effects`、`motion` 和 `clock`，它叠在白天外观上。夜间外观只属于写出它的文件，不随 `base` 继承：以海岛假日为基础的主题若也要日夜切换，需在自己的文件里写出 `night`（“以当前主题新建”会自动带上，连同 `dusk` 和 `daylight`）。

```jsonc
"daylight": { "mode": "clock", "day": "06:30", "night": "18:30", "duskMinutes": 60 },
"night": { "colors": { "surface": "#0B1622" } },
"dusk": { "colors": { "surface": "#2A1A2E" } }
```

| 键 | 作用 | 取值 |
|---|---|---|
| `daylight.mode` | 由什么切换外观。`clock`：从 `day` 到 `night` 用白天外观，其余时间用夜间外观。`system`：Windows 应用为深色模式时用夜间外观，浅色模式时用白天外观，没有黄昏 | `clock`（默认）、`system` |
| `daylight.day`、`daylight.night` | 按时钟切换时，白天开始和夜晚开始的时间；白天可以跨过午夜 | `HH:mm`，默认 06:30 和 18:30 |
| `daylight.duskMinutes` | 夜晚开始前显示黄昏外观的时长（仅 `clock` 模式） | 15–180，默认 60 |
| `dusk` | 可选的黄昏外观，写法与 `night` 相同，叠在白天外观上；必须同时写出 `night` | |

`mode` 写了未知的值、`duskMinutes` 超出 15–180、只有黄昏没有夜间外观，或任一外观里有无效颜色，文件都无法使用。用户可以在设置的“当前主题”中选择“跟随系统深浅”或改动白天时段；跟随系统时白天时段不能修改。每次切换（白天到黄昏、黄昏到夜晚、夜晚到白天，或 Windows 在浅色与深色之间切换）时，岛上旧外观的画面会在 1.6 秒内淡出；关闭动画时直接切换。每种外观都要通过下面的可读性规则。

## 可读性保证

主题只决定“好不好看”，不会让信息变得难以辨认：

1. 每个带下限的颜色在应用前都会与底色、渐变的每个色标、纹理最亮和最暗的方块以及弹出层比较对比度。
2. 低于下限的颜色沿原有色相调亮或调暗（取需要改动更小的方向），只调到刚好达标；达标的颜色原样保留。半透明的颜色一旦需要调整，会按叠在底色上的效果改为不透明色。若背景有明有暗、任何亮度都无法全部达标，则采用最差情况最好的亮度（绝不比原色更差），并在设置页标明“无法全部达标”。
3. 应用颜色、时间颜色、封面取色等用户在别处选择的颜色，也按当前主题的底色做同样的处理，所以浅色主题下浅色系的预警色、柠檬绿时间等仍然清晰。
4. 设置页的“当前主题 › 可读性调整”会列出每一处调整；无法加载的主题文件会列出原因（JSON 错误、未知颜色项、ID 重复等），不会被选中。

内置主题全部按原样通过这些规则（测试 `PanelThemeTests` 逐项检查）。

## 设计流程

制作一个主题可以按下面五步走，示例主题“赛博朋克：边缘行者”就是这样完成的。

1. **收集参考**：截取作品或品牌的代表画面，记录场景的明暗、主色、点缀色与反复出现的图形元素。
2. **提炼角色**：把颜色分到面板的角色上——底色（大面积、最暗或最亮）、文字三级、强调色、语义色（预警、告警、错误）、装饰（描线、阴影、渐变、纹理）。
3. **先定底色与文字**：底色决定一切对比度；文字三级按 7 : 4.5 : 3 拉开。
4. **再定点缀与应用色**：应用色彼此要能区分，并且在底色上不低于 3:1（预警与告警同时也是文字，需 4.5:1）；预警与告警要符合直觉（黄、红）。
5. **验证**：在设置页逐一查看收起、展开、提示与弹出层，确认“可读性调整”为空或可以接受；必要时回到第 3 步。

## 新主题的设计说明

**液态玻璃（浅色 / 深色）**：参考 Apple 的 Liquid Glass、liquid-glass-react 和“透明岛”概念，以及小米 HyperOS 4 泄露的“清透”模式。岛下的桌面被模糊（见上方“玻璃”）。浅色是乳白色调（`#C2F7F9FC`），深色是石墨色调（`#C8121419`），浓度刚好让正文在纯黑或纯白桌面上都保持 7:1。镜面高光描线左上最亮、右下再亮一次，约半分钟沿边缘转一圈（`drift`）；内缘集光让边缘像厚玻璃。悬停是 `lens`（玻璃珠顶部聚光），按下是 `jelly`（参考 xiaofangstudio/liquid-glass-web 的果冻按压：压扁 1.05 × 0.93、只压底边、弹簧回弹），没有粒子。

**海岛假日**：白天是从暖沙（`#FFF6E8`）到海沫的渐变，深海色文字，泻湖青强调色，珊瑚色衬线时间，描线是“海岸线”（青、天蓝、沙色）。夜里是月光海面：藏青到深青的渐变，灯笼金时间，岛下一圈淡淡的夜光。动效：描线像涌浪一样缓慢呼吸，颜色像水一样流动，白天偶尔有一道阳光闪过、夜里换成更稀的月光；悬停时底部涌来一道小浪，白天按下留下阳光闪点（`sparkle` + `star`），夜里浮起荧光浮游（`ember` + `firefly`）。

**海岛假日 2**：同一座海岛的明信片版本，与第一版并存。白天是晴空（`#A8E1F8`）渐入地平线的暖雾，约三分之二处是海平线，下面是泻湖青的海面（`decor.horizon`），海平线上一道阳光，海面上是阳光投下的柔和水光（`decor.caustics`），展开面板右上角落着棕榈叶影（`decor.palm`）；深海色文字，泻湖青强调色，晒红的珊瑚色圆润时间（Fredoka 字体，`rounded` 样式），芒果色指示条，扶桑红“已喜欢”，描线是“海岸线”（泻湖、天空、沙滩、珊瑚）。黄昏（入夜前一小时）天空转为蜜桃色，海面被夕阳映暖，海平线变成金色，描线换成日落色。夜里是深海藏青（`#001E3C`），月金色海平线下是深青海面，水面上淡淡的月光，灯笼金时间，岛下一圈淡淡的夜光。收起的小岛只保留天空，海平线不会横穿时间。动效：描线像涌浪一样缓慢呼吸，颜色像水一样流动，白天偶尔有一道阳光闪过、夜里换成更稀的月光；悬停时底部涌来一道小浪，按下时从控件边缘扩出一圈水波（`splash`），完成的按压白天冒出气泡（`bubble`）、夜里浮起荧光浮游（`firefly`）。

**像素方块**：非官方的像素风，灵感来自方块沙盒游戏，不使用任何游戏的画面、字体、贴图或标志，全部由颜色和方块画成。深板岩色底加 5% 的方块颗粒（`texture`），2 DIP 的阶梯圆角（`pixel`），左上亮、右下暗的斜面描边，无模糊的硬阴影；岛上和面板弹出层的文字不做平滑，面板里的圆角都变成直角。文字用“聊天”式的高饱和色：白字、黄色方块时钟（`pixel` 时间样式）、绿色强调，指示条像经验条一样是绿色；弹出层是深紫配紫框。设置窗口跟随 Windows 的浅色与深色，不随面板主题变化。动效全部分 4 格跳动：悬停是 `slot`，按下是 `bevel`，完成后从边缘弹出方块粒子；没有环境光，空闲时不占 CPU。

## 示例：赛博朋克：边缘行者

这是一个非官方的同人配色，只使用颜色，不包含作品的任何画面、标志或字体。

**画风分析**。《赛博朋克：边缘行者》由 TRIGGER 制作，延续了 80 年代动画的复古未来感：大块平涂的赛璐璐色、高饱和霓虹，夜之城的夜空偏紫黑，街道被品红与青色招牌照亮；《赛博朋克 2077》标志性的黄色贯穿片头和界面；角色上，露西的发色在青与粉之间渐变，丽贝卡是薄荷绿配粉色；画面中常见扫描线、色差错位和带切角的 HUD 线框，月亮是反复出现的意象。

**角色分配**：

| 来源 | 颜色 | 面板角色 |
| --- | --- | --- |
| 夜之城的靛青夜空与街道青雾 | `#0C0C22` → `#101030` → `#0A1F33` | 底色与自上而下的渐变；菜单与提示 `#10102A` |

| 青色霓虹、露西的发色 | `#00F0FF` | 强调色、焦点、进度底轨：霓虹只留在细处 |
| 品红霓虹 | `#FF2A6D` | 收起时的辉光、已喜欢、指示条进度 |

## 示例：明日方舟：终末地

非官方同人风格，灵感来自《明日方舟：终末地》界面的工业感：只用颜色和几何图形，不使用游戏的画面、标志、字体或文字。设计与取舍的全部记录在仓库之外的设计文档里，这里只列主题文件里能看到的部分。

**风格**。终末地的界面是“一家工业公司签发给操作员的设备面板”：纸与墨为体，中性色占九成以上，只用一处信号黄指向“此刻要看的、要按的”。官网和工作室界面是白纸，游戏里的操作面是炭黑，所以这个主题有两个外观，**跟随 Windows 的应用深浅色**（`daylight.mode = system`，在设置里仍可改成按时间），而不是按白天黑夜：这是设备的显示模式，不是氛围。

| 来源 | 颜色 | 面板里的角色 |
| --- | --- | --- |
| 纸与墨 | 浅色 `#FAFAFA` / `#191919`，深色 `#141414` / `#EDEDED` | 面板底色与三级文字（深色外观里主要文字 16:1） |
| 信号黄 | `#FFFA00` | 深色外观是线与字：强调色、指示条、播放进度、律动条、时钟预设；浅色外观只做填充：选中的页签与分段、指示条、选中日期的黄字配墨块；白底上不写黄字、不画黄细线，焦点色改用墨色 |
| 通知橙 | `#FC6C00`（深色）/ `#B84A00`（浅色） | 额度告警 |
| 危险红 | `#FF5A52` / `#C61218` | 超额、错误、已喜欢 |
| 稀有度色阶 | 蓝、青、绿、紫（深浅各一组） | 各应用列的身份色；cursor 等用灰阶，身份不占用语义色 |
| 切角铭牌 | `effects.cut = 10` | 岛的轮廓：底角 45° 斜切，刘海的肩部是直斜线，收起的胶囊保持圆头（资源读数是药丸）；控件圆角收到 2 DIP |
| 印刷标记 | `decor.tab`（信号黄）与 `decor.hatch`（斜纹） | 展开面板底边的两处：左端一小段信号条，右端一条淡斜纹；通知窗左缘是整条信号竖条 |
| 宽体时钟 | `wide` 样式（Unbounded） | 取代终末地的宽体数字字体 |

**动效**。机械、不弹跳：悬停是行高亮加左缘竖条（`caret`），按下是压暗（`shade`），键盘焦点是四角角括号（`brackets`），弹簧取 `firm`；没有环境光、粒子、呼吸或台阶，空闲时不占 CPU。

**检查**。两个外观的每个颜色都原样达标，没有任何自动调整：主要文字至少 7:1，其余 4.5:1，滚动条滑块 2:1，选中项上的墨字 16:1；高对比度下换成系统色，切角、斜纹和信号条都不画。

文件在 [`endfield-industrial.json`](../../src/BrimDeck.Core/Themes/endfield-industrial.json)。主题卡片上的 alpha 徽章来自文件里的 `stage`，名称本身不带 alpha。
