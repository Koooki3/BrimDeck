# 灵动提示

收到通知时，刘海、胶囊或指示条会从原位置连续展开，显示应用图标、标题和摘要；悬停约 0.25 秒或单击可查看详情，几秒后收回原形态。Windows 自己的横幅与通知中心保持不变，BrimDeck 只是同时显示一份。全部在本机处理，不使用任何云端服务。

## 开启

设置 › 通知 › 灵动提示 › 启用灵动提示（默认关闭）。开启后：

- 展开面板多出“最近通知”页（铃铛图标，有未看的通知时带红点；提示弹出过但你没有悬停、点开或在本页看到时，仍算未看），列出保留期内的通知，可展开查看正文、打开应用、删除、暂停或清空。
- 通知的外观跟随[面板主题](themes.md)：与刘海、胶囊、指示条和展开面板使用同一套底色、渐变、扫描线、边缘、阴影或辉光与文字颜色。会发光的主题在通知到达时闪亮一次。应用颜色只用于图标旁的小圆点、进度环和首字母，并按主题自动调整到清晰可读。

## 通知来源

| 来源 | 说明 | 默认 |
|---|---|---|
| Windows 应用通知 | 读取当前用户在 Windows 通知中心里的应用通知：来源、图标、时间和文字。不会读取应用内部的聊天消息，也不会清除或修改通知中心。 | 开启 |
| brim-notify 命令 | Windows 上的 `BrimDeck.Notify.exe` 与 WSL 中的 `brim-notify` 主动发送提示。 | 开启 |
| WSL 桌面通知 | 所选发行版中 `notify-send` 等标准桌面通知（freedesktop D-Bus）。 | 关闭，按发行版单独开启 |

### Windows：轮询与事件模式

BrimDeck 作为普通桌面程序运行时，Windows 不向它发送通知变化事件，因此使用**轮询模式**：每 2.5 秒检查是否有新通知（约 2.5 毫秒 CPU），每 15 秒完整读取一次列表；新通知通常在 0.2–2.6 秒内出现。实测空闲开销约为单个核心的 0.36%。

注册**身份包**后改用**事件模式**，几乎没有空闲开销。安装目录的 `identity\Register-NoticeIdentity.ps1` 会为当前用户注册一个只含清单的身份包，以安装目录作为外部位置，不复制、不移动任何文件，也不需要管理员权限。Windows 只在“开发者模式”下注册这种未签名的包；没有开发者模式时保持轮询即可，功能完全相同。注意：开发者模式是系统级设置，打开后任何未签名的应用包都能在这台电脑上安装，不只是 BrimDeck 的身份包；如果不需要事件模式省下的那点开销，建议保持关闭。卸载 BrimDeck 时会为执行卸载的用户自动注销；升级时保留。同一台电脑上的其他 Windows 用户若也注册过，需要各自运行 `Register-NoticeIdentity.ps1 -Remove`（Windows 不允许普通权限移除其他用户的包）。

```powershell
powershell -ExecutionPolicy Bypass -File "<BrimDeck 安装目录>\identity\Register-NoticeIdentity.ps1"
```

首次使用如果 Windows 尚未决定是否允许读取通知，设置页会显示“允许访问”按钮；被拒绝时可在 Windows 设置 › 隐私和安全性 › 通知中修改。

### Windows：应用的名称、图标和分类

Windows 通知里的应用标识有时看不出是哪个应用，BrimDeck 会这样处理：

- **Edge 安装的网页应用**（如 WhatsApp 网页版、Facebook）：按网站命名，例如“WhatsApp”，不显示为 Microsoft Edge；不同网站是不同的应用，可以分别设置规则。正文末尾重复的网址会去掉。
- **Chrome 等浏览器里网站的推送**：浏览器会在最后一行附上网站地址。BrimDeck 去掉这一行，并按网站区分来源，例如“Gmail · Google Chrome”，这样可以只静音某个网站。只有两行文字的通知保持原样。
- **没有开始菜单快捷方式的桌面程序**：使用它注册的名称和图标（注册表 `HKCU\Software\Classes\AppUserModelId`，图标只取本机文件）。
- **Windows 没给名称的常见程序**：哔哩哔哩、钉钉、Gemini、经典版 Outlook 等按 BrimDeck 内置的名称显示；Squirrel 安装的 Electron 程序（如 Discord、Slack）显示为程序名。
- **老式托盘程序的气泡提醒**：Windows 没有给出名称时显示为“托盘程序”，不再显示一串数字；只有程序路径的桌面程序显示为程序名。
- **默认分类**：Windows 通知不带分类。Claude、Codex（ChatGPT）、Gemini 桌面版和 Cursor 的通知标为“任务”；Windows 系统提醒、Windows 安全中心、NVIDIA App、Adobe Creative Cloud、Clash Party/Clash Verge、截图工具、联想和英特尔的工具等标为“提示”；聊天、邮件和浏览器保持“消息”。
- **来电**：聊天应用（QQ、微信、Teams、WhatsApp、Discord 等）和手机连接的通知如果是语音/视频通话邀请（“邀请你进行语音通话”“Incoming call”“is calling you”等），显示来电标记，并像闹钟一样立即弹出（该应用设为低优先级时除外）；“未接来电”不算。
- **被替换的通知**：应用用同一条通知更新内容时（比如 QQ 把新消息合并成一条），Windows 会删掉旧通知、加入新通知。如果两者来自同一应用、标题相同，并且在同一次读取中出现，BrimDeck 会更新原来那条提示，不会留下两条。
- **emoji 的显示**：WPF 不支持彩色字体，emoji 显示为单色；由多个 emoji 组合成的序列（如家庭、彩虹旗）可能显示为方框，国旗显示为两个字母。这是平台限制，文字本身不受影响。

### WSL

在“WSL（默认关闭）”下打开某个发行版后，BrimDeck 会：

- 把通知代理复制到该发行版默认用户的 `~/.local/share/brimdeck/brimdeck-agent`，并写入 `bridge.json` 与版本记录。代理分别为 x64 与 ARM64 构建，各有 glibc 版（Ubuntu、Debian、Fedora 等大多数发行版）和 musl 版（Alpine）；BrimDeck 按发行版的 `uname -m` 和程序加载器选择。都不能运行的发行版（32 位 ARM、RISC-V，或 C 库不在标准位置）会在设置中显示为不受支持，30 分钟内不再重试；
- 添加 `~/.local/bin/brim-notify`。只有内容与 BrimDeck 写入的完全一致时才会更新它；同名的其他文件或符号链接一律保持不动，并在设置中提示冲突（此时可直接用 `~/.local/share/brimdeck/brimdeck-agent notify`）。所有文件都先写到新建的临时文件再改名替换，不会顺着符号链接写到别处；
- 只在发行版**已运行**时通过 `wsl.exe` 启动代理，绝不为了接收通知而启动发行版，也不修改 WSL 配置或替换系统的 `notify-send`。WSL 1 与 WSL 2 发行版都支持；
- 代理本身是一个 `wsl.exe` 会话，它运行时 WSL 不会自动停止发行版和虚拟机。因此代理每分钟检查一次：发行版中该用户除代理自身、WSL 的 init/中继进程和会话组件（`systemd --user`、`(sd-pam)`、`dbus-daemon`/`dbus-broker`）以外已没有任何进程（终端、后台任务都算在内），并且持续 5 分钟，代理就自行退出，让 WSL 照常停止发行版、释放内存。设置中显示为“代理已退出”。之后发行版停止、再次运行时，代理自动重新接入；如果发行版因为其他原因一直没有停止，BrimDeck 最多每 30 分钟再启动一次代理，不会反复重启。

代理按 `DBUS_SESSION_BUS_ADDRESS`、`$XDG_RUNTIME_DIR/bus`、`/run/user/<uid>/bus`（后两者须属于该用户）、`~/.dbus/session-bus/<machine-id>-<显示编号>`（无 systemd 时由 X11 自动启动的总线）的顺序查找会话总线；暂时没有总线时每 3 秒检查一次。

代理按会话总线的情况自动选择：

| 情况 | 处理方式 |
|---|---|
| 没有通知服务 | 代理成为该会话的标准通知服务，应用的按钮会显示在详情中并回传给应用 |
| 已有通知服务且允许监视 | 旁路观察，不替换原服务；原服务的按钮不提供 |
| 已有通知服务且不允许监视 | 显示限制；`brim-notify` 仍可用 |
| 没有会话总线 | 显示限制；`brim-notify` 仍可用 |

作为通知服务时，代理声明 `body-markup`：正文中的标记按纯文本显示（去掉标签、解码 `&lt;` 等），标题始终原样显示。带 `x-canonical-private-synchronous`、`synchronous` 或 `x-dunst-stack-tag` 提示的通知（音量、亮度等）按同一应用、同一标签更新同一条提示；带 `transient` 提示的通知照常显示，但不保存到已保存的通知中。图标是 `/usr/share/icons` 或 `/usr/share/pixmaps` 内的符号链接、且链接一直指向这两个目录内时，按实际文件显示（Debian/Ubuntu 的主题图标多为链接）；其他符号链接仍不读取。

移除：在设置中关闭该发行版，然后在发行版中删除 `~/.local/share/brimdeck` 与 `~/.local/bin/brim-notify`。

## brim-notify 命令

```text
brim-notify "构建完成" --body "测试已通过"        显示一条提示
brim-notify run -- dotnet test                  运行命令，结束后显示结果（退出码与用时）
brim-notify "部署中" -r deploy --progress 40      同一 -r 键更新同一条提示（任务进度）
brim-notify status                              检查 BrimDeck 是否在接收
```

选项：`-b/--body`、`-s/--source`（来源名称）、`-c/--category`（message、task、success、warning、error、info）、`-p/--priority`（low、normal、high，仅作提示，只有你为该应用设置的“优先”才会真正提高优先级）、`-i/--icon`（本机图标文件，相对路径从当前目录算起；WSL 中不带 `/` 且当前目录没有同名文件时按图标名查找）、`--id`（重试时去重）。Windows 上的程序名为 `BrimDeck.Notify.exe`，位于安装目录。

退出码：0 已送达（或被你的规则静音），1 用法错误（包括按 BrimDeck 的长度上限截短后仍超过 64 KB 的消息），2 被拒绝（包括 `stop` 找不到这个键的计时器、秒表或日程），3 BrimDeck 未运行、灵动提示已关闭，或没有及时回复（此时提示仍可能显示）；`run` 返回所运行程序自己的退出码。标题和正文在发送前就按 BrimDeck 的上限截短。

## 时间类通知

闹钟、计时、倒计时、邮件和日程提醒会自动识别，按种类显示：

| 种类 | 来源 | 显示 |
|---|---|---|
| 闹钟 | Windows 时钟的闹钟、计时器结束、专注时段结束的系统通知 | 高优先级；可“打开应用”回到时钟 |
| 计时进行中（秒表） | `brim-notify stopwatch` | 实时显示“已计时 12:03”，可停止 |
| 倒计时 | `brim-notify timer` | 实时显示“还剩 24:59”和进度环；到点时再次弹出（高优先级），可取消或“5 分钟后再提醒” |
| 闹钟 | Microsoft To Do 的任务提醒 | 同上 |
| 邮件 | Outlook（新版和经典版）、邮件和日历、Thunderbird、Foxmail 等的新邮件通知；浏览器里网页邮箱（Gmail、Outlook 网页版、QQ 邮箱、网易邮箱等）的通知；WSL 中带 `email` 类别的桌面通知 | 普通通知 |
| 日程 | Microsoft 365 日历、邮件和日历的日程提醒；Outlook 中像提醒的通知（“15 分钟后”“现在”或以“下午3:00 - 下午3:30”开头的一行）；Teams 的会议提醒和“会议已开始”；Google 日历网页版的提醒，网页邮箱中像提醒的通知；`brim-notify event` | 高优先级，显示“14 分钟后开始”“进行中”；`brim-notify event` 由 BrimDeck 自己在开始前提醒 |

- 识别依据是应用的 ID（AUMID）和通知文字，只在本机内存中判断，不保存原始通知，不读取邮箱或日历。识别属于启发式：Outlook、Teams 的提醒格式随版本和语言变化，未识别时按普通通知显示。
- 设置 › 灵动提示 › 时间类通知 列出本机装有哪些相关应用（只检查是否安装，不读取应用数据）。这些应用的提醒来自 Windows 通知，需要开启“Windows 应用通知”。
- 闹钟、倒计时到点和日程提醒为高优先级，不受“每 10 秒最多 3 次”的限制，但同一来源每分钟最多响 3 次（每个 Windows 应用各算一份，brim-notify 和 WSL 应用各共用一份），其余排队等待，所以脚本一次设下的大量计时器不会挡住其他应用的闹钟；你把该应用设为“静音”或低优先级时照常不弹出。锁屏、演示和暂停期间同样只计入汇总。开始时间已过去 10 分钟以上才补录的日程按普通通知记录。电脑睡眠期间到达的 Windows 通知在唤醒后只记录、不弹出，但其中 10 分钟内刚发出、或日程正好在前后 10 分钟内开始的提醒仍会照常提醒。未提醒的计时器、日程和正在运行的秒表最多保留 200 个，超出时最早创建的会被移除（并记入日志）。
- 实时文字由一个共享的每秒节拍刷新，只在岛上或“最近通知”页正显示进行中的计时时运行；倒计时和日程由 BrimDeck 按时钟计算，休眠唤醒、修改系统时间后会立即重新计算。错过超过 10 分钟的提醒（电脑休眠、BrimDeck 未运行）不再弹出，只在列表中显示“已于 15:30 结束”。
- 限制：Windows 不对外提供时钟应用里正在运行的计时器、秒表和闹钟列表，也不提供系统通知上的“贪睡/关闭”按钮，所以时钟的闹钟只能在响起时显示，不能代为贪睡；需要在岛上看计时可用 `brim-notify timer`。日程同步（直接读取 Outlook 或 Windows 日历）尚未支持，目前依靠应用自己发出的提醒通知。

```text
brim-notify timer 25m "番茄"                   倒计时 25 分钟，到点提醒（也可 1h30m、90s）
brim-notify timer --at 15:30 "开会"              倒计时到 15:30
brim-notify stopwatch "构建" -r build            秒表，显示已用时间
brim-notify stop build                         停止秒表，或取消倒计时、日程（与发送时的 -s 来源一致）
brim-notify event "周会" --at 15:00 --remind 10m --ends 16:00   日程：开始前 10 分钟和开始时提醒
brim-notify "新邮件" --kind mail                  把普通提示标为邮件（或 alarm）
```

- 时间写法：`15:30`（下一次出现的 15:30）、`2026-10-24 15:30`，按 **Windows 的时区**理解（WSL 发行版的时区不同也一样）；也可写带时区的 ISO 8601，如 `2026-10-24T15:30:00+08:00`。夏令时跳过的时刻顺延到跳变后，重复的时刻取较早一次。
- 时长写法：`90s`、`25m`、`1h30m`、`2d`；倒计时 1 秒到 31 天，提前提醒最多 7 天，时刻须在 1 天前到 1 年内。相对时长从 BrimDeck 收到时开始算，不依赖 WSL 的时钟。
- 没有给 `-r` 时会生成一个键并打印到标准输出，可用 `brim-notify stop 键` 结束；给定 `-r` 再发一次会重新开始。
- 未完成的倒计时和日程在开启“保存最近通知”时会在重启后继续；还没提醒的日程不受保留时长清理。

## 显示规则

- 提示不会抢占输入焦点，不会在展开面板或你正在操作的详情上弹出；面板展开时只在铃铛上增加红点。
- 默认停留 6 秒，高优先级 8 秒；悬停、查看详情或用键盘操作时暂停计时。
- 同一应用 0.8 秒内连续的通知合并为一条并显示数量；每 10 秒最多自动展示 3 次，其余进入最近通知；等待超过 30 秒的普通通知不再补播；一条合并通知最多停留两倍时长。
- brim-notify 和 WSL 的通知按发送方写下它的时间判断新旧：发出时已等待超过 30 秒（高优先级 5 分钟）的消息只记入最近通知并标为未读，不再弹出。等待时间由发送方用自己的时钟计算，WSL 与 Windows 时钟不一致也不会误判；时间类通知按各自的提醒时间处理。同一条消息（相同事件 ID）在 BrimDeck 重启后再次送达，只要最近通知中还有它，就不会重复记录或弹出。
- 用 `-r` 更新的通知按最新一条消息计时：弹出时显示“刚刚”，而不是被替换的旧通知的时间。
- 通知到达时如果鼠标正停在岛上，不会自动展开详情，需要移开再移回或单击。
- 优先级：你正在操作的内容 > 高优先级通知 > 普通通知 > 配额提醒 > 切歌提示。闹钟、倒计时到点和日程提醒属于高优先级（见“时间类通知”）。
- 锁屏、切换用户、手动隐藏、全屏隐藏规则生效时不显示内容；Windows 专注会话、演示模式和 BrimDeck 自己的“暂停提醒”期间不弹出，结束后只显示一次数量汇总。Windows 单独的“请勿打扰”开关没有公开接口，无法识别，可使用 BrimDeck 的暂停。
- 多显示器：默认在前台窗口所在、且显示 BrimDeck 的显示器上弹出；该显示器的面板被隐藏时通知留在最近通知中，不会跳到其他显示器。
- 通知快捷键（默认不设置）：有提示时打开详情并可用键盘操作（Tab 切换、Enter 确认、Esc 关闭）；没有提示时打开最近通知。

## 隐私

- 最近通知默认保存 24 小时、最多 500 条，使用 Windows 为当前用户提供的加密（DPAPI）写入 BrimDeck 安装目录的 `notices` 文件夹（只对当前用户开放；安装目录不可写时改存 `%LOCALAPPDATA%\BrimDeck\notices`）；可关闭保存（仅在内存中保留，此时应用图标也不写入磁盘）、修改保留时间和保存位置，或一键清空。还可以选择定期清空：每次退出时、每天或每周清空整个列表（每天、每周清空时保留尚未提醒的计时器、日程和正在运行的秒表）。提醒响起或秒表停止后，从这一刻起重新计算保留时间。
- 更换保存位置时，已读入的列表会和新文件夹中已有的通知合并后写入新位置，写好后再删除旧文件；文件夹是链接、不归当前用户所有，或者其他账户也能改动其中的文件时不会读写，设置页会说明原因；后一种情况可以在设置页点“仅限本人访问”，把文件夹设为只对当前用户和系统开放。网络位置（NAS、Samba 共享）上的文件夹只检查是否为链接，因为其属主是服务器上的账户。文件夹只在选定或更换后检查一次，并且在后台进行，网络位置无响应时不会卡住界面；每次读写前还会再确认文件夹和 `notices.dat` 都不是链接，`notices.dat` 是链接时不会读取它。保存的文件暂时无法访问（被占用、所在的盘或网络位置不可用）时，BrimDeck 稍后自动重试，在此之前不会写入，以免覆盖原有记录；这段时间里删除或清空的通知，在文件读回后也不会再出现。文件确实损坏时提示清空重建；当前账户没有读取权限（例如文件由以管理员身份运行的 BrimDeck 创建）时，可以重试，也可以清空重建。每次保存都先把新文件写入磁盘再替换旧文件，断电不会留下损坏的文件。
- 删除或清空只删除 BrimDeck 自己的记录，不会通知来源应用；只有在提示上点关闭或按 Esc，才会把 WSL 桌面通知按“用户关闭”回报给来源（与关闭桌面通知气泡一致）。关闭灵动提示或清空时，正在显示和排队等待的提示会一并取消。
- 不保存原始通知内容、附件或头像；应用图标只来自 Windows 或本机文件，不下载任何网络图片。网络路径、链接或快捷方式指向的图标会被拒绝。
- 诊断日志 `notices.log` 只记录错误类型、错误码与调用位置，不含标题和正文。
- 本地通道只允许当前用户在本机连接（命名管道，拒绝网络访问）；通知内容只作为文字显示，不会作为命令执行，也不会打开其中的链接。
- 每个应用可单独设置：关闭、静音（只进入最近通知）、正常、优先，以及到达时显示“标题和摘要 / 仅标题 / 仅应用”。

## 兼容性（实测）

| 场景 | 结果 |
|---|---|
| Windows 11（26300）未注册身份包 | 可读取通知快照；变化事件不可用，使用轮询模式；端到端 0.2–2.3 秒 |
| Windows 通知中的图标 | 打包应用可取得图标；缺失时显示应用首字母 |
| 打开来源应用 | 打包应用通过应用列表启动；桌面应用通过开始菜单注册的应用 ID 启动；不支持时在详情中说明 |
| WSL Ubuntu 26.04（systemd 会话总线，无通知服务） | 代理成为通知服务；gdbus/notify-send 通知显示；按钮回传 `ActionInvoked` 与 `NotificationClosed` |
| WSL 已有通知服务 | 旁路观察，正确取得通知 ID 与关闭事件 |
| 多显示器（含负坐标、125% 缩放副屏） | 在前台窗口所在显示器弹出，位置与缩放正确 |
| 8 套内置主题 × 刘海、胶囊、指示条 | 外观逐一核对 |

未实测的情况（如锁屏中的真实行为、注册身份包后的事件模式）以设计为准，可能需要在你的环境中确认。
